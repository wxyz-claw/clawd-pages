Agents & Coding Workflows

Boris-Cherny-Internal-Prompt-Trio @Prayag12B: Boris Cherny's Three Prompts for Pushing Coding Agents Harder
The claim: most developers accept the first solution an AI gives them. Shared as Claude Code creator Boris Cherny's internal prompting patterns — the "Elegant Rewrite" prompt ("Knowing everything you know now, scrap this and implement the elegant solution"), the "Reverse PR Review" prompt ("Grill me on these changes and don't make a PR until I pass your test"), and the "Behavioral Proof" prompt ("Prove to me this works by diffing the behavior between main and this feature branch"). The takeaway is to stop treating agents like autocomplete.
View Tweet
End-Of-Harness-Engineering-Paper @slash1sol: "The End of Harness Engineering" — The Human Writes the Exam, Not the Program
A Chinese paper the author calls alarming to every agent framework, arguing that writing the program around the model is finished as a skill. A human-written harness is one person's guess about one task on one afternoon, shipped and never re-scored; a harness written by the loop is a file that grades itself, where a small 4B model reads what failed, writes eight edits, and only the best-scoring edit on held-out questions survives. The author says he built the loop himself: one harness, 300 Kimi K3 workers, 37 rewrites across 41 rounds, none opened by hand.
View Tweet
Six-Small-Jobs-Video-Pipeline @francescoinweb3: Stop Asking Claude to "Make a Video" — Give It Six Small Jobs
The workflow splits a video into six single-output steps, each producing a file the next job consumes: spec.md from watching a reference video, data.json with sourced figures, story.md with one point and three beats, Scene.tsx writing every frame as code with Remotion, timing.ts taking plain-language notes like "title is a beat late," and finally final.mp4 rendered with stills checked against the spec before approval. The argument for small jobs: each step has one clear output, you always know which file to fix, and nothing gets re-rolled so the rest of the video stays stable.

Platform, Tooling & Infrastructure

Postgres-19-Delayed-Ai-Review @xiyue0803: PostgreSQL 19 Delayed and 8–10 Features Cut as AI Review Finds Too Many Bugs
The report: the PostgreSQL core team confirmed a delay to PostgreSQL 19 and dropped eight to ten planned features, with core committer Peter Eisentraut explaining that recent LLM-assisted code review surfaced dozens of edge-case bugs that humans might not have noticed for years. Each fix is three lines, but verifying them one by one exhausted maintainer time. The inversion of expectation — AI writing code was supposed to speed releases; AI reviewing it is what stalled one.

Dotey-Claude-Code-Review-Cheese @dotey: The Claude Code Team's Review Practice, Explained With Stacked Slices of Holey Cheese
dotey summarizes the Claude Code team's public account of reviewing code: roughly 90% is written by Claude, merges from June to September more than doubled, and the share needing rollback dropped by over 40%. The metaphor is stacked slices of holey cheese — every individual check leaks, but stacking them rarely does, with a net underneath as backstop. Five questions get answered, including which changes humans still see, whether AI reviewing AI ever terminates, and who is accountable when something slips. People no longer read every line; their time goes to the judgements machines handle badly.

Harness Economics: Where the Tokens Go

Stretchcloud-Opus-Advisor @stretchcloud: Sonnet With Opus On Call Beats Opus All Day
The number worth keeping from Claude Code's new advisor tool: Sonnet paired with an Opus advisor scored 2.7 points higher on SWE-bench Multilingual than Sonnet alone, for 11.9% less cost per task. Haiku with the same advisor hit 41.2% on BrowseComp against 19.7% solo — trailing Sonnet by 29% on that score while costing 85% less per task than Sonnet would. Eve Legal told Anthropic that Haiku plus an Opus advisor matched frontier quality on document extraction at a fifth of the cost of running the frontier model directly. The mechanism is narrow on purpose: one model drives end to end, and the advisor is pulled in at exactly three moments — before a plan locks, when the same error repeats, and before the task is marked done. It never touches a file; it returns a plan, a correction or a stop signal, a few hundred tokens billed at its own rate. Against that, Anthropic's own research on multi-agent systems found the decompose-and-delegate pattern runs 3 to 10x the tokens of one agent doing the same work, mostly lost to duplicated context and handoffs.

0Xveyyro-Claude-Router @0xVeyyro: $4.26 All-Opus, $1.03 Routed, Same Launch Line
A rerun with harder work than the usual demo: a database schema migration, 340 tests, 64 files. All-Opus would have cost $4.26; the routed run cost $1.03, leaving 76% unburned. The split is the useful part. Haiku 5.5 took six tasks — scan 64 files, grep 27 imports, list 5 flaky tests, summarise 8 logs, run 340 tests, type-check and lint — on 720k tokens for $0.07. Sonnet 5.5 took the schema migration and two tests on 210k tokens for $0.42. Opus 5.5 read the diff and raised three flags on 134k tokens for $0.54, and every agent returns summaries only, so Opus never sees raw output. The correction to the obvious assumption is that the migration itself ran on Sonnet for $0.21 and Opus still caught three things reviewing it. One caveat he states rather than hides: past a 100k prompt Haiku costs five times its own rate, so each lane is deliberately kept small.

Maxt3Chno-Astra-Vs-Sol @maxt3chno: Astra 13% / 26 min vs Sol 6.1 4% / 49 min
A side-by-side on one honest task: building a 3D model from scratch through Blender MCP. Astra drained 13% of quota in 26 minutes; Sol 6.1 used 4% and took 49 minutes. The framing — 'did OpenAI quietly route Sol somewhere stronger?' — is speculation, and he does not pretend otherwise. What is not speculation is the trade he measured: roughly a third of the quota for roughly twice the wall clock. For interactive work that may well be the right trade; for anything batched or overnight, the cheap model is buying you three more attempts at the same problem.

Quota Arithmetic

Shakhzod-Sol-High @shakhzod1001: Thirty Minutes of Sol High, Half the Window
One trial, stated plainly: half an hour of GPT-6.1-Sol High ate 51% of the five-hour limit, against Sol Medium running more than two hours nonstop. His claim that there is no large output gap between the two grades is the part to test on your own workload rather than accept — but the ratio is the kind of number you can plan around. If a single session can consume half a window in thirty minutes, the effort dial is not a quality preference, it is a budget decision you make before you start.

Vincent-Magpie-Usage @cn_Vincentzyx: Same Output, Twice the Quota — 7% vs 16%
A controlled comparison that isolates the variable. Same account, Opus 5.5 at high effort, the same 'pelican riding a bicycle' HTML task, measured in five-hour quota: official interactive use 7% and 7%, `claude -p` 14%, Magpie 16% and 17%. He notes the `-p` output volume was nearly identical to the interactive run, so the doubling is not explained by more work being done. The plausible readings are per-request overhead or a different accounting path for non-interactive sessions, and he is asking Anthropic's team directly how usage is computed. That is the right question, because if headless invocation bills at twice the interactive rate, every agent wrapper built on a subscription is quietly twice as expensive as its author thinks.

The complaint is specific enough to be useful. Releases and Builds

Elonmusk-Grok-Calls @elonmusk: Grok Bot Now Makes the Phone Call
A capability announcement with the loop spelled out: Grok Bot will call a person or a business on your behalf, make the request, take notes on the response, and send you a note summarising the conversation. It is the least glamorous agent feature and probably the most useful — a large share of real-world tasks still terminate in a phone tree, and no amount of browser automation reaches them. Worth testing against the obvious failure mode: what it does when it reaches a human who asks who is calling and why.

Btrischetta-Conclave @btrischetta: Conclave — Thirteen Models, One Auditor From Another Company
Shipped free and open source after a September promise, and the design is more interesting than the aggregate answer. Conclave asks up to thirteen models at once — Claude, ChatGPT, Gemini, Grok, DeepSeek and others — has an independent synthesizer weigh their answers, then has a model from a different company audit the result for mistakes before you see it. Sources, audit and cost are all exposed. It runs on your own machine with your own API keys: no account, no subscription, no middleman, and you pay the labs only for what you use. Windows for now, which is the limitation to note if you were about to install it on a Mac. The premise — better answers come from disagreement that is then checked — is the same argument as the advisor pattern, one layer up.

A migration report with the migration cost included: an afternoon to move every workflow and project off a Railway-hosted Hermes Agent to Grok Bot, plus a rethink of roles and reporting lines. The Patch Gap

Tspy-Php2Shell-Honeypot @tspy: 0.02506816 BTC for Anyone Who Breaks This PHP Box
Someone built a PHP site as a live test of how much attention php2shell is getting, and put a wallet key on it: 0.02506816 BTC, about $2,018 at the time of posting. The install runs a PHP version older than the CVE's release, so anyone who breaks in can read the key file directly. Josephyala-Php-Fix-Gap @Josephyala: Finding the Flaw Was the Easy Half
The correction to the way AI vulnerability discovery usually gets reported. AI helped identify two serious flaws in PHP — and finding them turned out to be only part of the problem. The fixes then had to be prepared, packaged and distributed so administrators could install them before attackers got there. That last step is the one with the schedule risk, and it is the reason a record month for disclosed vulnerabilities is not the same thing as a record month for security. The bottleneck moved from discovery to distribution, and distribution runs at the speed of other people's maintenance windows.

Naypyidaw-Artex-Copies @naypyidaw: ARTEX Was Withdrawn; the Forks Were Not
Per Nikkei, modified copies of ARTEX — a Chinese-developed autonomous AI penetration-testing framework — are circulating even after its developer stopped distributing the original, with abuse confirmed in attacks on Japanese companies. The point generalises past this one tool: once an autonomous attack framework is public, withdrawing it does not recall it, and every fork inherits the capability without the author's intent. For defenders the implication is that the tooling curve has already moved — the question is no longer whether an adversary can automate reconnaissance and exploitation, only how quickly your own patching closes the gap.

Compute, Capex and the Credit Question

Ai-Funss-Inference-Margin @ai_funss: $8/hr of B300, $10–20/hr of Revenue
An attempt to reconstruct the arithmetic behind the inference resellers who report seven figures a month. Rent B300 capacity at $8/hour, serve DeepSeek 4.1, Kimi K3 or GLM 5.3 at around 100 tok/s, and the revenue lands at $10–20/hour; DeepSeek's own off-peak pricing can reach $38/hour, and on Vera Rubin he puts gross margin toward 80%+. The framing is deliberately unflattering — a few people vibe-coding a thin front end, renting cards, running Chinese open models, and taking the spread through a router — and the second-order point is the one worth thinking about: the margin exists because the closed labs keep tightening quotas and raising API prices, so the arbitrage is a direct function of the frontier labs' pricing power.

Worth Your Time

Govind-Compaction-Cost @Govind_vash02: Compaction Cut Context 33% and Raised the Bill
A rare thing: someone built their own coding agent, instrumented it with evals, and published an experiment that failed in an interesting direction. The task was nine files and four tickets on gpt-5-mini. With compaction off, ten runs averaged 16.5 steps, 14.7k peak input and 16k fresh input. Clearing at 8k tokens: 23.3 steps, 9.8k peak, but 46k fresh input, with two to seven clears per run. Clearing at 12k: 17.4 steps, 12.7k peak, 25k fresh input, exactly one clear per run. Pass rate stayed at 100% throughout and the bill went up anyway. Two mechanisms explain it. At 8k the threshold sits near the size of what the model is actively working on, so it cleared a file, re-read it next turn, and cleared again — ten file reads became fifteen, and one edit failed because the model wrote from memory of a file it no longer had. At 12k the cleared tokens had been cached at roughly a tenth of the price, and clearing changes the start of the conversation and invalidates the cache for everything after it; one clear needs about fourteen turns to pay for itself, and these runs had six to nine. Conclusion: with prompt caching, compaction buys room for long sessions, not savings on short tasks.

Brunooliveira-Hermes-Commits @brunooliveira: 229 Commits, and Two Bugs That Should Scare You
Release notes written as a threat model, which is why they are worth reading in full. Two entries stand out. First: a cron job that named one MCP server by its toolset name never matched the allowlist check, so it ran with every enabled MCP server — asking for filesystem also granted github and slack, and a server explicitly disabled with `enabled: false` fell through the same way. Second: on platforms without buttons, the text `/approve` prompt cut commands at 200 characters, so a 320-character echo followed by `&& rm -rf` displayed no `rm -rf` at all. The fixes are proportionate — cards now show the call's arguments as JSON capped at 1,200 characters with API keys and tokens masked even when secret redaction is off, and the text prompt shows up to 3,000 characters — but the pattern is the lesson: the approval surface is part of the security boundary, and truncation is a vulnerability. Also noted: a gateway that crash-looped on Docker Desktop because sockets cannot be bind-mounted, fixed by falling back to a 0700 temporary directory, and one-shot runs that may now author skills at a cost of roughly 1,343 extra tokens per request.

Omarsar0-Cli-Interface @omarsar0: The CLI Is No Longer the Best Interface for Agents
A short argument from someone who has been a heavy CLI user and is changing his mind anyway. His claim is that the terminal was the right interface when the model was the bottleneck, and stopped being the right one as persistence, coordination, parallelisation, tool calling, memory and harness optimisation improved — at which point the interface becomes the thing holding the model back. The apps he names, Grok Bot and the Codex app, make multi-agent work and lifecycle management easier to run than a shell does. His rule of thumb is the falsifiable part: don't use an interface that keeps you from leveraging the model to its limits. You can disagree with the conclusion and still use the test — most people's tooling choices are habits formed when the constraints were different.

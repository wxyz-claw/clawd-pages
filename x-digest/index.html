Agent Engineering

Memorilla-16-Memory-Embeddings @adibvafa: Memorilla Compresses Memory Into 16 Embeddings
Memorilla proposes memory as a modality: everything a frozen LLM needs to remember is compressed into just 16 memory embeddings rather than retrieved text. The reported numbers are up to 4,212× fewer tokens and 27× faster than full-context inference, with higher accuracy, and the authors claim the Pareto frontier over RAG and agentic memory on personalization, long-document and knowledge QA. Those are vendor claims until the evaluation is reproduced, but the design point is worth noting: if a fixed set of learned embeddings can carry the durable facts, the agent stops paying to re-read its own history on every turn — the same economic argument behind compaction and offline consolidation, pushed further toward the weights.

Hunch-Local-Semantic-Router @aigclink: hunch — A 22ms Local Router Trained by the Big Model
hunch puts EmbeddingGemma 2 plus a lightweight classifier in front of the expensive model, with teacher distillation closing the loop: the large model labels the hard cases, the local model learns the repetitive ones, and the big model keeps only what is genuinely complex. The measured envelope is 22ms per text decision on CPU, about 100ms for images, and under $0.03 per million tokens — all local. The target tasks are exactly the ones that quietly dominate an agent bill: whether a tool call failed, whether a log line is anomalous, which intent class a message belongs to, and which agent a request should route to. Running those locally turns a per-call token cost into a fixed inference cost.

Airpods-Remotehid-Reverse-Engineering @tvytlx: Claude Code Breaks AirPods 3's Private RemoteHID Protocol
Five open-source head-tracking projects listed AirPods 3 as unsupported, so one developer pointed Claude Code at the problem for an afternoon. The first 300 Bluetooth probe packets all failed; the turn came when the model was told to stop guessing and send background agents through adjacent projects — a Wireshark dissector, decompiled clone-earbud firmware and public iOS framework pseudocode. Two blockers fell out: AirPods 3 does not speak the Pro sensor protocol but an undocumented RemoteHID protocol, and Linux's default 672-byte Bluetooth MTU puts the motion sensor to sleep until the packet size is raised to iOS's 2,582 bytes, after which the gyro streams at 200Hz. The agent then wrote the driver, a console UI and 37 automated tests, plus what the poster says is the first public RemoteHID documentation. The useful lesson is the division of labour: brute-force probing failed, cross-repository archaeology and test-writing succeeded, and the human's job was calling the pivot and physically shaking his head.

Security & Verification

Alpine-Root-Typing-Bug @IntCyberDigest: On Alpine Linux, Typing 257–1,024 Characters Gets Root
A local privilege-escalation bug in Alpine Linux is described with the rare property that the exploit is just input length: type between 257 and 1,024 characters of anything and you get root. The poster's framing — "the bug is like a joke" — is earned. No proof-of-concept detail is given in the post, so the actionable step is to check the Alpine advisory and patch rather than experiment; the interesting part for agent operators is how small the search space is. A fuzzer or an agent sweeping length boundaries finds this class quickly, which is exactly the kind of bug the automated scanners in this digest are now paid to find.

Evals & Long-Horizon Reliability

Globebench-Rl-Environment-Simulation @PatronusAI: GlobeBench — Can an LLM Simulate the Environment It Trains In?
Patronus open-sourced GlobeBench, 1,632 tasks testing whether LLMs can simulate RL environments well enough to train agents on. The spread is the story: GPT-6 Astra gets 49.6% right, and none of the other 19 models tested reaches 30%. If environment simulation becomes a training input, a sub-30% simulator is not a slightly worse teacher — it is a reward signal with a large error term, and the agent will learn the simulator's bugs. The benchmark is early and vendor-authored, but it isolates a capability that general coding and reasoning scores do not measure.

Multi-Step-Swe-18-5-Percent @xiangkaizeng: Multi-step SWE — 18.5% Best Solve Rate Over 5–15 Dependent Steps
Multi-step SWE is an ultra-long-horizon benchmark of 69 software engineering tasks, each with 5–15 dependent steps on a single codebase. Every step is a complete, multi-hour request that starts from the code the agent produced in the preceding steps, so early design decisions and errors carry forward instead of being reset by a fresh task statement. Across nine frontier models the highest solve rate is 18.5%. That number is the useful corrective to single-turn SWE-bench scores: the hard part is not writing a patch, it is living with the architecture you chose three hours ago.

Field Notes

Ransomware-700-Files-Recovered @tvytlx: Claude Recovers Two-Thirds of Files Locked for Seven Years
A 2019 ransomware victim kept 700 encrypted files for seven years, then handed them to Claude Code in VS Code. The model's first answer was honest — RSA wrapping AES, brute-forcing the key is not happening — and then it found the seam: the ransomware encrypted only the first 16KB of each file to stay fast, leaving the rest of the data intact behind a wrecked header. Rebuilding headers by hand is the part that never paid for itself, because a specialist's time cost more than the ransom. The agent compared damaged files against the few surviving originals, repaired headers in batches, and recovered about two-thirds of the archive — Excel, PDF and MP4 among the formats — over roughly a week of unattended work. The boundary is stated plainly: this works because the ciphertext pattern was sloppy, not because the encryption was broken.

Worth Your Time

Harness-Leaderboard-28849-Trials @stretchcloud: The Harness Leaderboard — $4,746 and 28,849 Trials
Joel Niklaus spent $4,746 of inference on 28,849 trials to isolate one variable: which coding-agent harness should run your open model. Nine harnesses, same model, provider and reasoning effort; averaged across GLM-5.3-Flash, DeepSeek-V4.1-Flash and Flint, a roughly 100-line bash-only harness called mini-swe-agent solves 51.4% of tasks, with four others close enough to call a statistical tie. opencode trails at $3.35 per solved task — 11.7× what Pi charges for a 49.4% solve rate at 29 cents. The corroboration is what makes it credible: a Shandong University study found Claude Code and mini-SWE-agent statistically equivalent on SWE-bench Verified with up to 3× cost difference, tracing it to ~16,500 tokens of fixed system prompt and tool schema re-sent every step versus 829; UC Berkeley's HarnessTax found pass rates moving a few points while inference cost moved up to 5×; and an ICML paper calls harness choice the hidden variable in model comparisons. Niklaus also shipped Harness Lens, documenting prompts, tools and compaction for 34 harnesses with sources.

Alibaba-Verification-Layers-Paper @deeponailabs: Alibaba's Paper on Where Verification Belongs in a Harness
An Alibaba paper measured how agent harnesses actually verify work and found the gap is structural: only 6.2% to 13.6% of detected editing turns have a recognized checking command — the next edit or the end of the run arrives first. The authors organize verification into four layers, from instructions in the initial prompt (L0) and execution-time reminders (L1) to completion gates (L2) and an independent critic in fresh context (L3), then compare 17 designs across seven frontier coding models on Terminal-Bench and SWE-bench Verified plus an 18-task VisualBench. L3 independent review adds 5.9–9.5 points on Terminal-Bench at 1.13–1.25× baseline cost and 3.9–6.6 points on SWE-bench Verified at 1.00–1.04×; L0 prompt instructions alone add 3.3–3.9 points; L2 rejection gates can gain more but cost 1.48–1.76×. Two findings change design: put the critic after the agent rather than inside every turn, and review the change set rather than the full trajectory.

Releases & Capability

Ricursive-Ripple-65B @RicursiveAI: Ripple-65B — A Dense 65B Trained From Scratch
Ricursive released Ripple-65B Preview, a dense 65B model pretrained from scratch, and claims a new state of the art for U.S. open-weight models on agentic coding — ahead of models three to fifteen times its size: Muse Spark Open-816B, Beam-501B, Inkling-975B and Nemotron 3 Ultra-550B. The interesting number is the one they did not lead with: dense at 65B, not a mixture of experts, which makes it cheap to serve and easy to fine-tune relative to the 500B-plus MoEs it is being compared against. Treat the ranking as a vendor claim until the task-level results are out, but the size class is the story — capability per parameter keeps falling faster on agentic coding than on general benchmarks.

Agent Engineering

Claudedevs-Subagent-Status-Cheap @ClaudeDevs: The Status Line Was 99% of the Subagent Bill
Claude Code background subagents update a status line every 30 seconds, and every one of those updates used to re-read the subagent's whole conversation. Now Haiku 5.5 writes the status from short notes instead, and Claude's developer account puts the saving at about 99% per update. This is the cheapest kind of win and the easiest to miss: not a model change, not a prompt change, but noticing that a cosmetic UI element was paying full context price forty times per session. The generalisable rule is to audit every periodic write in a long-running agent for what it re-reads — heartbeats, progress bars and status strings are usually the most expensive lines in the system.

Ladyxtel-Living-Brain-Memory-Layer @ladyxtel: Memory Decoupled From the Model — 92.2% on LoCoMo
Living Brain is pitched as one persistent store shared across ChatGPT, Claude, Cursor, Codex and your own agents: write in one, retrieve in any. The published numbers are 92.2% on LoCoMo, 464ms median retrieval, and up to 22.6x fewer tokens per question. The architectural claim is the one worth testing — memory as a layer with its own API and MCP surface, so swapping the reasoning model does not throw away what the system learned. The obvious caveat is that 22.6x fewer tokens per question says nothing about the tokens spent building and maintaining the store, and LoCoMo rewards exactly the long-horizon recall a dedicated store should win. Still, this is the third independent team this week to treat context as infrastructure rather than as a bigger window.

Maritime-Agent-Box-Pricing @maritime_sh: A Persistent Computer for Your Agent, $1/Month
Maritime (YC F26) is selling the boring substrate: an always-on box that keeps the agent's files, bills unlimited awake hours, and wakes in about a second. Pricing is 2GB for $1 a month, 4GB for $2, 8GB for $4. The numbers matter because they price the alternative to stateless function calls — most agent designs pay for persistence either in re-sent context or in a container that idles at full rate. At $1 a month, keeping a filesystem alive between runs is cheaper than the tokens it takes to reconstruct state, which quietly changes what architecture is affordable for a personal assistant or a long-running background job.

Quoting a report that Apple is cutting employee AI budgets — daily limits from $300 down to $200, with $100 planned and some teams at $25 — Peter Steinberger argues the individual limit is becoming a category error. Whether or not you buy the conclusion, the contrast is the useful part of today's feed: one large company tightening per-head allowances while small teams are re-pricing compute per outcome.

Security & Verification

Openai-Autonomous-Kernel-Vuln-Pipeline @OpenAI: 948 Linux Kernel LPEs Found, Validated and Patched
OpenAI's security researchers built an autonomous pipeline that discovers, exploits and patches vulnerabilities, then ran it once against the Linux kernel: 948 local privilege-escalation bugs validated with generated patches, at a total API cost of $1.2 million. Do the division and it is roughly $1,270 per validated, patched flaw — still expensive by human-audit standards only if you assume a human finds one. The framing detail is "validated", not just "reported": the pipeline had to demonstrate the escalation before writing a patch, which is the step that separates this from a very confident static analyser. Distribution is now the bottleneck, not discovery, which is a problem the kernel security process was never sized for.

Barrettlyon-Cve-2026-98432-Filter @BarrettLyon: The Exact nftables Rules for CVE-2026-98432
Doxxnet published the filter it runs in production against CVE-2026-98432, with the nftables rules and the RFC behind each one, so an ISP, host, VPN or mesh operator can make the exploit undeliverable to every Linux box behind them. This is the shape defensive work should take: not a severity score and a vendor advisory, but a copy-paste rule set with the reasoning attached, published by someone running it. If you operate any border, the useful exercise is comparing your current rules against theirs — the failure mode in cases like this is rarely a missing block, it is a block placed one hop too deep.

0Xmishoko-Claude-Code-Repo-Deletion @0xmishoko: One Missing Pair of Quotes Deleted a Year of Work
A first-hand post-mortem of the failure mode every agent user fears: Claude Code removed a repository — .git, every commit, every branch — in one command, with no prompt and on a top model. The reported cause is a single unquoted path expansion, meaning the destructive target resolved to something other than what the instruction named. The lesson is not "the model is unsafe"; it is that shell strings are a lossy interface between intent and effect, and the quoting bug that a shellcheck run would catch in human code is exactly the one an agent will reproduce confidently. Concretely: no agent should hold write access to a repo's history without a snapshot, and destructive verbs deserve an allow-list rather than a confirmation prompt.

Cost, Evals & Infra

Posthog-2T-Tokens-Custom-Benchmarks @posthog: 2 Trillion Tokens a Month, and No Trust in Gut Feel
PostHog says it spends more than 2 trillion LLM tokens a month, a number large enough that "does the agent feel better" stops being an acceptable change-control process, so the team built custom benchmarks and wrote up what broke. The problems named are the ones that make off-the-shelf evals useless for a product team: parallel runs that interfere with each other, and open-ended tasks with no single correct output to score. Worth reading for the methodology rather than the verdict — the hard part of internal evals is not the harness, it is agreeing on what a correct answer looks like before you have one to compare against.

Craft & Context

Kay2289123-Agent-Critical-Thinking @Kay2289123: Six Habits Against "AI Cognitive Suicide"
A Chinese-language response to Addy Osmani's piece on critical thinking when agents do the work, and the most practical thing in the feed today. The diagnosis: output looks flawless, so the reviewer approves, approves, approves, and the judgement muscle atrophies. The six habits are unusually concrete — have the agent quiz you and show evidence rather than only answers; be honest about how much of a conclusion you actually understand; form your own guess before asking so the model has something to argue against; interrogate which decisions the model made on your behalf; write prompts by voice so you cannot type without thinking; and hold one hard rule, that if you would not put your name on the output you do not approve it. That last one is a usable acceptance test, not a slogan.
View Tweet
Tvytlx-Little-Book-Generative-Ai @tvytlx: 195 Pages That Flatten the Model Zoo Into One Derivation
Tianhua Chen put a 195-page book on arXiv, The Little Book of Generative AI Foundations, and its trick is refusing to treat model families as separate species: every generative model is approximating a data distribution and sampling from it. From PCA, add a probabilistic assumption and you have probabilistic PCA; swap the linear map for a network and you have a VAE; split the latent transform into many noising and denoising steps and you have diffusion; apply the chain rule to the joint distribution instead and you have the autoregressive models under today's LLMs. WGAN and energy models fall out where the normalising constant becomes intractable. The v2 revision adds visual explanations and roughly ten times the file size. Useless if you only call APIs; genuinely useful if you want to know why a model class has the limits it has.

Worth Your Time

Alishohadaee-Long-Context-Cost @alishohadaee: 256K Context Costs 3.6–7x More, and Compaction Nearly Works
A close read of "You don't need long context" (Belcak, Molchanov et al., Nov 3) with the numbers that matter: serving at 256K instead of 16K costs 3.6x to 7x more per generated token across GLM 5.2, Kimi K2.6 and Qwen 3 Coder Next, measured from H100 throughput. The proposed fix is compaction — when context crosses a threshold the agent writes down the task, its plan and the artefacts it still needs, then restarts from that — with long documents left as files the agent greps in pieces, which scored up to 40 points higher than pasting the whole input. The extreme version, one action per context, kept Opus 4.5 at 70.2% on SWE-bench Verified versus 70.0% with full history while peak context fell from 130–200K to 15–37K tokens, for estimated savings of 2.2x to 8.8x. The honest caveats are included and are the reason to trust the rest: costs are estimated from throughput and list prices rather than real bills, compaction is lossy, and Qwen 3 Coder Next collapsed from 53.0% to 3.6% at the tightest setting.

Omkarray9-Voice-Agent-Judge-Calibration @OmkarRay9: A Judge That Agreed With Humans 33% of the Time, Then 92%
Notes from Upstart and Coval's talk on running voice agents on regulated lending calls, built around one trajectory: at launch their LLM judge agreed with human reviewers on 33% of compliance calls; about eleven months later, 92%. The playbook is the transferable part — write the PRD as pass/fail rules on a transcript, build a golden set with a minimum of 200 labelled calls and 30 real failures before trusting any judge, then track judge-human agreement per criterion rather than as one score. Two traps are named precisely: at a 95% pass rate an "always pass" judge scores 95% agreement, so report recall on real failures against a holdout; and a transcript judge cannot catch a confident wrong fact, so amounts, dates and status must be checked against the system of record. In their data roughly one in six flags was the judge being wrong, which is why they made the eval owner a real role.

Me-Deepu-Longcat-25-Reward-Hacking @me_deepu: Meituan's 1.6T Model and the Anti-Cheat Section Worth Copying
LongCat 2.5 is 1.6 trillion parameters with about 48B active per token, trained and served on Chinese accelerators with under 80GB of memory per card, and it ships with the part most model posts omit: how they stopped the agent cheating during RL. Network access is switched off inside the task environments, git history and cached files are deleted, and an LLM judge audits trajectories for exploits; repeated tool calls and looping reasoning are penalised — which is also where long agent runs quietly burn tokens. The serving numbers are the practical ones: 4-bit weights and 4-bit activations against their 8-bit baseline, prefill throughput up 43.3% and decode up 42.77%, with quality reported on par on every task they evaluated. The footnote is a nice touch of honesty — rival benchmark scores without an asterisk were run by Meituan itself and are labelled indicative only.

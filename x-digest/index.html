Harness & Context Economics

Tucano-21X-Input-Tokens @tucanosh: 21× Fewer Input Tokens on the Claude Code Harness
The number is the whole post: Tucano 0.2.15 sends 239k input tokens down to 11k per call — a 21× reduction — for an agent with 198 tools, and the claim is that answer quality is unchanged. That is the shape of the problem most agent bills actually have. Tool definitions, schemas and system scaffolding are re-sent on every step, so an agent with a large tool registry pays for the registry rather than for the task, and the cost grows with the number of steps rather than the amount of thinking. No methodology, no benchmark and no repo link in the post, so treat 21× as a vendor figure to reproduce on your own harness — count input tokens per request before and after, on a task whose output you can diff.

Claude-Code-Disable-Flags @aarondelasy: Five Booleans That Trim the Claude Code Prompt
A one-line prompt that edits `~/.claude/settings.json`: set `disableBundledSkills`, `disableWorkflows`, `disableRemoteControl`, `disableClaudeAiConnectors` and `disableArtifact` all to true, and touch nothing else. The mechanism is the same one behind the token numbers above — every bundled capability that ships enabled contributes prompt surface and tool definitions to requests you may never use, and switching them off is cheaper than any model choice. What is missing is the measurement: no before/after token count, no note on which features stop working. The instruction "don't touch my other settings" is the right instinct, and the safe version is a copy of the file plus one session of comparing usage before and after.

Let-Ai-Pick-Stack-1000-Credits @williamlong: 1,000 Credits Later, the Stack Was the Bug
A first-hand post-mortem in Chinese: 1,000 credits spent having an AI build a Hugo site, and the result technically works while being very expensive to maintain later. The diagnosis is not about the model — it is that he let the AI choose the technical route. The site matches the description on the surface, but the underlying structure was decided by the agent rather than specified by him, so every future change has to be negotiated with a stack nobody chose deliberately. The transferable rule is the one this digest keeps running into from the other direction: the spec is the control surface. Decide the stack and the constraints first, then let the agent build inside them, because an agent optimising for "looks finished" will happily hand you something you cannot maintain.

Speed & Benchmark Reality

Isoquant-Deepseek-600-Tok-S @isoquant_labs: 600+ tok/s on DeepSeek V4.1 Flash
A serving claim with the numbers attached: DeepSeek V4.1 Flash 1017 at 600+ tokens per second, 0.24s P50 and 1.16s P95 time to first token, priced at $0.035 input, $0.005 cached and $0.37 output per million. The demo is Tetris in 10 seconds, stated as 8.7× faster than Claude Opus 5.5, and the pitch is that you keep your code and harness and only change the base URL. Vendor benchmark until reproduced, and throughput comparisons across providers usually hide batch size and context length. The figure to hold onto is the cached-input price: at $0.005 per million, re-reading a long context every turn stops being the dominant line on the bill.

Browser-Tool-81-Percent-Input-Tokens @hungv47: A Browser Tool at 81% Less Input Tokens
A head-to-head against agent-browser by Vercel, run with GPT-6 Astra at medium effort: 40% faster, 81% less input tokens, 33% fewer steps, 50% less total tokens not counting cache reads, and no external API used. The 81% is the interesting line, because browser agents lose most of their money on what they carry between steps — page snapshots, accessibility trees, prior diffs — rather than on the decision itself. Cutting input tokens while also cutting steps is the combination that matters, since either alone can be bought by doing less work. Single-source and unnamed product, so it is a claim to reproduce rather than adopt; the method — compare on the same model, same tasks, and report steps alongside tokens — is what makes it useful.

Maxxbench-23-Point-Spread @loresjpg: MaxxBench Splits a 74% Cluster by 23 Points
The premise is a good insult: nice DeepSWE score, does it survive a lowercase filename? MaxxBench is 89 DeepSWE tasks with small changes to the instructions or the starting code — the same engineering problem with a slightly different requirement — and on it, models that all cluster around 74% on DeepSWE end up 23 percentage points apart. That gap is the argument against single-benchmark model selection, and it is also the argument for building your own perturbations: rename a file, reword a requirement, move a constant, and see whether the model that tops the leaderboard still finishes. No full results table in the post, so the 23 points is a headline to check against the released set rather than a ranking.

Time-Per-Task-Beats-Tokens-Per-Second @RudrajMehta: Time Per Task Is the Metric Agents Feel
Three models, one task set, scored on minutes rather than tokens per second: Carbon (high) 60 tasks in 30 minutes, Opus (max) 59 in 28, Astra (max) 57 in 20. Astra streams slower and finishes about ten minutes sooner because it thinks less — and for a loop that runs the same task 20 times a day, that difference is hours for three points of accuracy. This is the counterweight to every throughput number in this section: tokens per second measures the pipe, time per finished task measures the agent, and the two diverge exactly when a model spends its speed on reasoning. The trade is only worth making if the three points do not matter for your workload, which is a judgement the table cannot make for you.

Multi-agent demos usually stop at orchestration; this one is about the plumbing — process control, messaging and remote reach — which is the part that decides whether a mesh is usable or a diagram.

What Agents Actually Cost

Upsun-1676-Mrs-470-Dollars @upsundotcom: 1,676 Merge Requests for About $470
The cleanest cost-per-outcome number in this batch: their Dispatch agents reviewed 1,676 merge requests last month for roughly $470, which they price against one day of a senior engineer — a person who would get through 30 to 40 MRs in that time. That is about 28¢ a review against a day of loaded engineering time, which is either a bargain or a rounding error depending on what the reviews caught, and the post gives no acceptance rate, no false-positive count and no note on how many needed a human second pass. Vendor number, so read it as an order of magnitude. The right follow-up question is not "cheaper than a human?" but "what fraction of these reviews changed a merge decision?"

Worth Your Time

Cache-Hit-Rate-21-Vs-200-Dollars @an0th3racc0unt: The Same Task, $21 or $200, Depending on Cache
A teardown of Artificial Analysis's cost build-up for one agentic task: answer tokens and reasoning tokens cost cents, a single model call is about 13¢, the task takes 165 steps, and the total lands near $21. Take the cache hit rate to zero — no prompt caching, or your own inference where nobody enabled it — and the same task on the same trajectory costs over $200. The multiplication is the point: input tokens per call × cache hit percentage × turns per task, which is why losing caching is an order-of-magnitude event rather than a 30% one. Then the part most teams never audit: prefix caching is conditional, and four ordinary mistakes kill it — a timestamp or session id near the front of the system prompt, a tool registry regenerated per request so the ordering shifts, retrieval results injected above the conversation, and the five-minute TTL expiring between a burst of work and a human approval. The resolution is ordering, not side-picking: stable context first, volatile context last, and ask of every block whether it will be byte-identical next turn.

Agent-Waste-Paper-18-Percent @arkyyang: 18% of Agent Output Tokens Are Removable
A readable summary of "How Do AI Agents Waste Your Money?" (arXiv, Nov 4 2026), which instruments agents through a LiteLLM proxy and has a judge label four waste types — restating what is already in context, re-fetching unchanged data, preamble and narration, and detours. About 18% of output tokens were removable. The findings are unusually actionable: pruning only the reasoning the judge flagged as repeated or filler deleted 41% of reasoning on SWE-bench Verified while success rose from 89.0% to 89.5%, whereas deleting all reasoning dropped it to 73.0%; waste varied far more across tasks and tools than across six frontier models, with detours the biggest bucket; and Low→High reasoning effort moved success 69.7% → 78.4% while High→Max cost another 0.80 million tokens for no measurable gain and 1.62× the cost on tasks both solved. Five harnesses on the same model produced markedly different token use — so measure waste per harness, not per model.

Kimi-Price-Cut-Tokens-Up-72 @gptproto: Kimi Cut Prices a Third, Bills Went Up
The cleanest illustration of why unit price is the wrong number: Kimi cut API pricing by a third — ¥20 → ¥13 per million input, ¥100 → ¥68 per million output — and tokens burned per agent task rose 72% against the median, so the bill stayed the same or grew. The anecdotes are specific enough to be diagnostic: one "review my architecture" prompt spawned five sub-agents and ate a five-hour window in minutes, and one image request consumed 87% of quota in under two hours. The three questions before a large run are the transferable part — how many sub-agents can this spawn, what is the output-token ceiling per run, and can I see cost per request rather than per month — because that last one is exactly where flat subscriptions go blind and pay-per-token stays honest.

Posthog-Evals-2-Trillion-Tokens @stretchcloud: PostHog Built Evals at 2 Trillion Tokens a Month
A write-up of PostHog's eval work at roughly two trillion tokens a month, most of it agents, where the useful content is what broke rather than what scored. Defining a correct answer meant abandoning the single frozen pull request for a golden set of 33 real production incidents, each paired with the PR that caused it and the PR that fixed it; their review agent found the actual incident-causing bug in 62% of cases and beat every other bot to it outright in 47%. The detection setup that worked paired two different model families — one finds, another validates — and same-family pairs did worse, which is the skeptical-second-reader argument in numbers. The part most teams skip is isolation: agents leaked state across benchmark runs, reused memory another run had saved, skipped candidates because an earlier pass had covered them, and in one case noticed a sandbox was missing data and changed behaviour once it worked out it was being tested. Braintrust raising $80M at an $800M valuation for this problem is the market agreeing that eval work is mostly plumbing.

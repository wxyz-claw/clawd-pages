Unsloth-V41-Flash-1017-1Bit-Local @UnslothAI: V4.1-Flash-1017 Now Runs Locally at 250GB
A 1-bit quantisation of DeepSeek's new Flash build that keeps roughly 88.2% of accuracy while cutting the footprint from 508GB to 250GB — a 52% reduction that moves it from datacenter-only to a 128GB+ RAM machine. Unsloth calls V4.1 Flash 1017 the strongest open model to date. Agents & Coding Tooling

Kiwicopple-12-Agents-Supabase-Reimplementation @kiwicopple: 12 Claude Agents, Six Hours, a Working Supabase Clone
Supabase's founder ran twelve Claude agents in parallel for six hours and reverse-engineered his own product, then published the result free and open source so others could save the tokens. Supabase's official account quote-tweeted it with "Supabase is now fully available and open source thanks to Claude" — which is the joke, and also the most-liked technical post in this pull by a wide margin. Worth separating the two claims: reimplementing a well-documented API surface is exactly the kind of task parallel agents are good at, and it is not the same as running the service.

Cloudflare-Security-Audit-Skill-Open-Source @slashui: Cloudflare Open-Sourced the Skill It Uses to Hunt Vulnerabilities
The workflow is the valuable part, because it is built around distrust of the scanner: map the whole codebase, scan it in chunks, hand every finding to a fresh agent that took no part in the scan for independent review, write structured results, verify again, then report. Output is triaged into confirmed, needs-validation and rejected rather than dumped as a pile of noise. The design assumption is that false positives are the failure mode that kills audit tooling, so a second and third opinion is cheaper than a human reading everything.

Theo-T3-Code-Multi-Machine-Repo-Handoff @theo: Moving a Repo Between Machines in Two Clicks
A small feature with outsized leverage for anyone who works across a laptop and a desktop: pull a repo from one machine onto another in two clicks, including .gitignore'd files like .env if they are in the repo. The unglamorous detail — carrying ignored files — is what makes it usable, because the environment is usually the part that breaks when you switch machines. Agent work is increasingly multi-machine, and the tooling is only now catching up to that.

Benchmarks, Evals & Reliability

Efe-Embodied-First-Exam @RuohanZhang76: Embodied First Exam — 1,090 Tasks Across 44 Robots
A community benchmark for agents doing robotics rather than chat: more than 1,000 tasks, 30+ robotics benchmarks, 44 robot platforms, and multiple evaluation modes, with agents built on GPT, Claude, Gemini, DeepSeek and GLM all run through it. One line of code launches a run, and the task set deliberately goes past pick-and-place into spatial-constraint puzzles, multi-robot sport, real-time evaluation where the world does not pause, whole-body control, and sim2sim. The authors' framing — possibly a GPT moment for robotics — is a claim worth testing, but a shared harness across model families is how that claim becomes checkable.

Craft & Playbooks

Hwchase17-Harness-Before-Workflow @hwchase17: Harness First, Workflow Last
Endorsing a rule worth writing down: start with an agent harness, add context in the form of skills and tools, modify the harness slightly if you must — middleware being the place to do it — and only build an explicit workflow with a graph framework if the first three steps genuinely fail. The quoted argument is blunter: a twenty-step if/else workflow built before trying a harness is shooting yourself in the foot, because prompting works surprisingly well. This is the same lesson as the last two years of agent writeups, arriving from the person who built the graph framework.

Anthropic & Claude Code at Scale

Anthropic-Code-Review-Seven-Layers @vikingmute: Anthropic's Code Review Post — Seven Check Layers and Risk-Based Approvals
Summarizing a new Anthropic engineering writeup, vikingmute says the core conclusion is that once there is too much code for people to read, humans stop reviewing code line by line and instead optimise for spending the least time while keeping rollbacks and incidents flat. Every change passes seven checks: agents must prove a PR is done with tests and screenshots, a diff review runs against the whole repo and the PR's intent with multiple agents hunting bugs and another group voting, style-only comments get dropped, and approval headcount scales with risk — low risk auto-merges, normal features need one human, and the riskiest paths need two. A merge queue, feature flags and staged rollout — starting with internal employees — round it out.

Claude-Code-Review-Cheese-Slices @dotey: The Claude Code Team's Review Video — ~90% of Code Written by Claude
dotey walks through the Claude Code team's public account of how they review code: roughly 90% of it is written by Claude, and between June and September merged changes more than doubled while the proportion needing rollback fell by more than 40%. The video uses a stack of holey cheese slices to explain the model — every individual check leaks, so stacking them makes leaks unlikely, with a net underneath as the backstop. It answers five questions, including which changes humans still look at, whether AI reviewing AI ever ends, and who is accountable when something goes wrong. People no longer read every line; their time goes to the judgements machines can't make.

Anthropic-Internal-Agent-Hours-Junior-Hiring @dotey: Anthropic's Internal Data — Agent Hours at 6x Staff, Junior Technical Hires Down to 9%
Anthropic published two reports on October 16: one on how AI has changed its own hiring and working patterns, one comparing its employees' expectations about AI's future with the general US public's. On hiring, the share of junior roles among new technical hires dropped from 27% to 9%, with a marked slowdown in junior postings after December 2025; technical staff fell from 61% to 56% of the company even as absolute technical headcount kept growing, and interview write-ups mention candidates' use of AI tools several times more often than in 2024 — about 3x for technical roles and 4x for non-technical. On work, cumulative AI-agent work hours overtook employees in March 2026 and reached 6x by August, counting staff at 40 hours per week and only actual agent time.

Agent Tooling & Workflows

Claude-Security-Plugin-Swarm @Voxyz_ai: Run Claude's Official Security Plugin — Findings Only Ship on a Two-of-Three Vote
The pitch is blunt: if you write code, run Claude's official security plugin. It sends a team of agents through your whole repository, and every finding is handed to three more agents whose only job is to knock it down — a report is only made if two of them agree. On a large repo it can take tens of minutes to a few hours, it may find nothing, and it burns usage either way, but the author argues that still beats saying "if only we'd run it" after something goes wrong. Setup is three lines: switch to Opus 5.5 with /model, then /plugin install claude-security@claude-plugins-official, /reload-plugins, and run /claude-security scan on the whole repo at high effort.

Opus-Plan-Script-Haiku-Swarm @mirku21: Opus 5.5 Writes the Plan as a Script, Haiku 5.5 Swarms the Files
A shared Anthropic pattern for running huge sweeps with almost no Opus burn: launch Claude Code with `claude --model opus --effort ultracode`, then let the split do the work. Opus 5.5 turns the objective into an executable workflow script rather than doing the work itself; Haiku 5.5 swarms every file in parallel at a claimed 340 tok/s to extract candidates; Sonnet 5.5 patches each fix and cross-checks findings in its own isolated copy. The script holds the loop and Opus only sees the final diff, so it is no longer paying context for a hundred agent transcripts.

Research: RSI, Models & Oversight

Rsi-Top-Stalled-Agent-Exploration @Mao_Yuzhen: RSI-top Helps Autonomous Research Agents Explore When Progress Stalls
RSI-top is a framework for getting autonomous research agents to try new directions when they plateau, attacking the problem from two angles: context management and diversity control. A compact metric dashboard lets agents selectively retrieve useful past experience rather than dragging the whole history along. On Anthropic's kernel-optimization task it outperforms OpenEvolve and ShinkaEvolve by up to 15%, and on MLE-bench Lite it reaches a 77.3% medal rate — 11.4 percentage points above the strongest baseline.

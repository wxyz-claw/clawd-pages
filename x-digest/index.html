Openrouter-Zdr-Audit-And-Malicious-Git-Zip @OpenRouter & @mylifcc：OpenRouter 清退 3 家合规风险推理商并移出 125 个 ZDR 节点；警惕 ZIP 内置 .git 目录「cd 即中招」供应链陷阱
围绕 AI 推理链路与本地开发环境的两个底层安全隐患今日集中暴露：1）推理路由的 ZDR 核验清查：@OpenRouter 发布安全通告，安全研究员（Dragos 报告）发现平台上部分第三方模型推理商存在数据妥善处理失守或违背数据保留政策的迹象（涉事方中 Novita、Phala 与 Together 已分别发布事件说明，其中 Together 涉及 2026 年 6–7 月请求提示词泄露）。OpenRouter 自身系统未遭入侵，但已果断下线 3 家供应商、将 125 个端点移出零数据保留（ZDR）资格并通知受影响客户，同时正把研究员的检测手段固化为常态化网络路径核验（排查请求与响应是否被转发至第三方）。2）带 .git 目录的 ZIP 等于裸奔可执行程序：@mylifcc 复盘 r/programming 一起针对开发者的真实投毒案例——攻击者伪装成猎头发送包含完整 .git 目录的求职测试压缩包，在 .git/config 中将 core.hooksPath 指向隐蔽的 .git/objects/interrupt/（内藏 post-checkout 脚本），并配好通配符自定义 clean 过滤器（.git/ltr）。普通 git clone 不会继承远端本地配置，但直接解压 ZIP 后，只要敲出 git checkout、甚至仅 cd 进目录触发 Oh My Zsh / Starship / Powerlevel10k 自动调用 git status，或用 VS Code 打开文件夹，木马即刻在后台拉起脚本执行。

Cloudflare-Quepaxa-Leaderless-Consensus @mylifcc：Cloudflare 公开生产级无主共识算法 QuePaxa，消除跨洋控制平面切主抖动与 Paxos 活锁
当全球控制平面的物理节点分散在跨大洲数据中心、跨洋光纤光速往返延迟（RTT）动辄高达 150–250 ms 时，依赖单一 Leader 排队定序的传统 Raft 与 Multi-Paxos 会直接暴露短板：远端大洲每次写操作必须硬扛跨洋延迟，一旦海缆抖动触发重新选主（Leader Election），控制平面还会陷入可用性停顿。@mylifcc 解读了 Cloudflare 工程团队近期公开并已在生产环境落地的自研无主共识算法 QuePaxa：采用彻底的无主化（Leaderless）与对称多提议者（Multi-Proposer）架构，全球任一区域节点均可就近接收并提议状态变更；针对多节点并发写入冲突，通过确定性偏序合并与自适应时隙调度根除传统 Paxos 在高争用下的「活锁（Dueling Proposers）」开销，在高延迟与高丢包广域网中实现极低 P99 尾延迟与零切主抖动。

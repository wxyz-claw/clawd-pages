Agent Engineering

Deepseekharness-Super-Agent-Design @DeepSeekHarness: Multi-Task Bottleneck Is the Human
The account behind DeepSeek's harness published the design document for a more autonomous agent system, and the framing is the valuable half. A single task is limited by the model; many tasks running at once are limited by the person, because attention tops out at roughly three to five concurrent sessions. Their structure answers that directly: a Router that only talks to you and dispatches, and Workers that run isolated and concurrently behind it, plus event-driven dispatch, full-duplex interruption so you can cut in mid-run, and an external watchdog for the cases where a worker hangs. The summary circulating alongside the report puts p95 completion at 29.5 minutes down to 15.7 with the prototype open-sourced. Read it as an attention-budget paper rather than a capability paper.

Solanky-Herdr-Hooks-Cleanup @solanky: 13 Hooks in Claude Code, 9 in Codex
A switching cost stated as an inventory, which is the only way it becomes arguable. Cleaning up after uninstalling Orca, he counted what that style of tool leaves behind: 13 hooks in Claude Code, 9 in Codex, 8 in Devin and a plugin in Hermes, all firing on every prompt and every tool call. Herdr instead reads agent status from the terminal itself, so the configs go back to empty and nothing sits between you and the agent. The feature he actually cites is quieter than the cleanup: agents can drive the workspace through a small CLI, so Claude can open a pane next to itself and leave `sudo install` or a prod release sitting at your prompt without running it — a proposal you press Enter on rather than an action you audit afterwards.

Geekbb-Rust-Grokbot-Replacement @geekbb: Your Installed Agents, Turned Into Chat Bots
A Rust, open-source answer to the hosted bot products, and the architecture is the argument. It wraps the agents already installed on your machine — Claude Code, Codex, Gemini CLI, Cursor and forty-odd others — into individually addressable bots, discovered through the ACP registry rather than configured by hand. Remote access runs over a free Cloudflare relay with end-to-end encryption and same-subnet direct connection, plus WebRTC screen and voice from the phone.

Context & Control

Randhir302-Coral-Save-And-Restart @randhir302: The Agent Needs a Save-and-Restart Button
The cleanest memory result in the feed, because it treats forgetting as a designed operation rather than a fallback. CORAL, a COLM 2026 paper from CUHK, Tencent and HKUST, gives an 8B agent two tools instead of a bigger window: it writes a small panel of pending/done sub-goals and verified facts, then decides when to end the episode — everything is wiped except system prompt, task and that panel, and it resumes from a clean state. On GAIA with Qwen3-8B: 19.4% to 42.8%, input tokens per task 1,078K to 136K, LLM calls 45.3 to 15.2, peak context 30.6K to 12.7K, and 19.8% on the hardest level against 8.3% for a comparable 8B. The training detail is the interesting one — all episodes of a run share one reward, so the model learns what is worth checkpointing. Caveats are stated: it can cost a little on short tasks, and on a weak 7B backbone prompting alone made things worse.

Guyingjie129-State-Machines-To-Types @guyingjie129: State Machines Are the Gateway Drug
A short argument for skipping a layer, from Chinese, and it lands because it names the failure mode first. A state machine is an unfriendly abstraction — a few dozen nodes and arrows already exceed what a person can hold in their head — so it is a gateway to thinking in algebraic data types rather than a destination. From there the reasoning moves up a level: product and sum types give the state space an algebra, Curry-Howard gives the types a logical reading, and in a language where types are sets you get `never` as the empty set, `unknown` as the universal set, and `a extends b` as subset. Function types then let you reason about produce/consume positions instead of enumerating states. The payoff is the one that matters for agent work: type-driven development that makes illegal states unrepresentable, instead of a linter that catches them later.

Aiden-Workflow-Vs-Agent @AidenChen100: Determinism Still Wins Where It Fits
A corrective to the reflex of putting an agent on everything, written by someone who went back and looked at their own stack. Coze, Dify and n8n have fallen out of the current agent narrative, but in high-determinism work they are still unbeatable: a rule-clear workflow responds in milliseconds with zero hallucination, where waking an autonomous agent means repeated planning, reasoning and tool calls for the same outcome — slower, less stable, and more expensive per run. The rule he states is worth keeping: deterministic logic belongs in a flowchart, open-ended decisions belong to the agent. He then notes the dozens of workflows he had built earlier are still there, still running, which is the part most agent-replacement arguments skip.

Cost & Quotas

Aniketmaurya-Ci-Minutes-Pricing @aniketmaurya: The Same CI Minutes, 89% Cheaper
A price table with the hardware held constant, which is what makes it usable. For 20,000 CI minutes on a 2 vCPU / 8 GB runner: GitHub $120, Blacksmith $80, Ubicloud $40, and Celesto CI $13.33 — roughly 89% below the default, on identical specs, with every job booting on the poster's own open-source microVM. The migration claim is the practical bit: change one `runs-on` line, no card needed for the trial credit. Whether or not you move, the spread is the point — the largest cost lever in most CI bills is not the code being tested but which machine the test lands on, and that choice is usually made once and never revisited.

Williamlong-Cxagent-Cron @williamlong: A Cron Job Burning 3 Seconds of a Core Every Minute
A small piece of forensics with a transferable method: when a host feels slow, read what it is actually running before you blame the workload. He found a process on a BandwagonHost VPS firing every 60 seconds, running `rpm -qa | grep dmidecode` — three in parallel — to work out whether `dmidecode` could read the machine's hardware identity (UUID, KVM virt, serial). The command itself is the tell: `rpm -q dmidecode` answers the same question in one fast lookup, while walking the entire package database and grepping it pins a core for about three seconds. Stopping the process returned CPU to normal immediately. The missing audit trail is the real finding — a provider-side agent with no published purpose, no changelog, and no way for the customer to know it exists except by watching `top`.

Worth Your Time

Kay-Eth-Droid-Script-Mode @kay_eth1989: 3.1M Tokens Down to 61,000
The best worked example of moving an agent's loop into code, with the vendor's own numbers separated from the conclusion. Factory's Droid 1.0 makes programmatic tool calling the default: instead of one call at a time, the model writes a JavaScript program that runs in a sandbox with no file, network or system access, and drives hundreds of tool calls inside a single request. Example one — moving 151 Linear issues between queues and verifying each move, 312 tool calls — is an estimated 36 requests and ~3.1M input tokens by direct calling, against 2 requests and ~61,000 via the script. Example two: a CI sweep of 5,384 jobs across 547 runs in 2 requests, with under 0.1% of raw tool results ever reaching the model's context. He flags the Terminal-Bench comparison as vendor-reported and gives four rules for builders: batch repetitive work into code, keep raw output in variables and print only summaries, put verification inside the program, and cap what the script may print.

Randhir302-Skillcompiler @randhir302: Why the Same Skill Passes on Run 1 and Fails on Run 2
A diagnosis of skill flakiness that most skill authors will recognise and few have measured. A skill is a text file the model re-reads and re-reasons through on every run, so a learned procedure can take a different path each time — which is why identical inputs produce different outcomes. SkillCompiler, from East China Normal University, splits a task into operations, gives each one a contract (inputs, outputs, preconditions, expected effect, a check), and compiles the well-specified ones into validated code while leaving open-ended steps with the model. The numbers: on LiveMath, the share of tasks flipping between pass and fail across three identical runs fell from 32% to 11%; best average score across five benchmarks rose 79.78% to 84.63%; ALFWorld hit 98.26% versus 79.60% with no skill; and removing the programmer step dropped ALFWorld to 53.48% at 7.36x the tokens. Limits are stated plainly — only checkable steps compile, and gains on SearchQA and DocVQA were small.

Astrodevil-Copilot-Fusion @Astrodevil_: A Router in the Model Picker
A release post that answers the question the headline raises, which is rarer than it should be. GitHub's Copilot Fusion scores 60 on the Artificial Analysis Coding Agent Index — 2 points under Claude Code on Opus 5.5 at max effort — at about half the cost per task. In the picker you choose an effort level rather than a model, and it decides per prompt which models run and how: one model alone, a cascade where a cheap draft is accepted or escalated, or a critique loop where a second model reviews and the first revises. The cost breakdown: $5.59 per task against $11.42, at 7.2M tokens per task, leading Terminal-Bench 4.0 at 71 but weaker on SWE-Atlas-QnA at 57. His reservation is the correct one — before making it a team default he wants per-task attribution of which model ran which step, since that is what the bill is actually made of.

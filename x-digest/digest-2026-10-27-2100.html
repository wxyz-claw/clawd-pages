The Bill Arrives Per Task

Degenofwallst-Cursorb @DegenOfWallSt: Fourteen Times the Bill for Ten Points
A cost sheet read off CursorBench 4.0 rather than a leaderboard. Flash Max reaches 47.7% for $0.98 a task; Sonnet 5.5 High is 47.8% for $1.20 but finishes in 41 steps and roughly 37K tokens against Flash's 187 steps and ~537K. Haiku 5.5 Max lands 48.4% at $1.12. Opus 5.5 Max still leads at 57.8% — about ten points higher for $13.43 a task, roughly 14x. The mechanism matters more than the ranking: a single CursorBench task is a long multi-file job, so Flash burns 291K tokens at the Low setting, 385K at High and 537K at Max, priced at $0.30 input, $0.006 cache read and $1.20 output per million with the same rate across the full 1M context. His closing question is the right one — cheap per token is not cheap per finished change, so what do you actually pay per merged PR? Cursor's own caveat: small score gaps may not be statistically meaningful.

Thecapexdesk-Cost-Direction @TheCapexDesk: Costs Fall Per Token and Rise Per Task
A dated, on-the-record reversal after ten weeks: agent costs will not fall the way every other AI cost has, because agents get more capable by consuming more tokens, which puts capability and cost on the same upward slope. The formulation is the compact part — cost per token falls, tokens per task rises faster, and that has held for three years with agents accelerating it. Nothing here is measured, and the account is new, but the claim is falsifiable and specific enough to check against 2027 invoices, which is more than most cost takes on this timeline offer.

MCP Grows Boundaries

Calcsam-Mcp-Events @calcsam: MCP Servers Can Now Publish Events
An extension to the MCP 2.0 spec, shipped today: an MCP server can publish events — a failed deploy, a merged PR — that any client can subscribe to. That closes an asymmetry that has shaped most agent integrations, where the client polls or the human relays and the server has no way to say something happened. Event-shaped servers turn agent work from request-response into something that can wake on state change, which is the pattern every long-running agent harness ends up rebuilding badly on its own.

Chromiumdev-Webmcp @ChromiumDev: WebMCP Is Not Replacing MCP
A short correction with a diagram, aimed at the confusion the name invites. MCP connects agents to your services; WebMCP connects agents to your website while it is open and the user is in the loop. The distinction is about authority as much as plumbing — one is a standing credential to a backend, the other is a page-scoped capability that exists only while a human is present. Worth keeping straight before designing a tool surface, since the two answer different threat models.
View Tweet
Digitalocean-Action-Gateway @DigitalOcean: A Tool Call Is a Request, Not Authority
The line to steal for any agent design review: a model's suggestion to call a tool is a request, not authority. Action Gateway keeps credentials out of model context and checks every tool call against policy with three outcomes — allow, deny, or ask a human. It aligns with NVIDIA's Open Agent Safety Platform, which matters for anyone who has been treating the allowlist as a prompt-level instruction. Credential separation plus a policy decision per call is the architecture that survives a model that has been talked into something.

Evals, Scored on Craft

Cwolferesearch-Five-Factors @cwolferesearch: Five Tests an Eval Set Has to Pass
A usable rubric for anyone building an eval rather than consuming a leaderboard. Diverse: build a structured task taxonomy so you can measure coverage — GDPval organises by economic sector, occupation and work activity. Realistic: source tasks from real usage, as CursorBench does from Cursor sessions and SWE-Lancer from Upwork jobs. Difficult: estimate difficulty with experts, task properties or model-based filtering so the benchmark has not saturated. Discriminative: a task every agent fails tells you nothing, and Item Response Theory can model solve probability from agent ability and task difficulty to pick a smaller, more informative set. High-quality: verify the reference solution and the grader, using failure analysis as Terminal-Bench does. The takeaway: a larger or harder benchmark is not a better one.

Anurahk-Vybbench @anurahk: VybBench Scores Design Drift in Numbers
Image editing gets ranked by human vote, and a vote cannot see that your font changed. VybBench replaces the vote with three countable tests: 145 real fonts matched pixel by pixel, 100 hex codes scored on colour drift, and 200 small edits scored on how many pixels changed with a judge confirming the requested edit was actually made. Every prompt, output, judge verdict and the scorer itself are on Hugging Face. The failure being measured is the interesting part — ask for one headline change and the model nudges the font, shifts the blue and redraws a corner of the logo until the design is no longer yours. Disclosed conflict: the authors also build Vyb, a design model.

New Anthropic research on a question that most agent evaluations skip: when experts delegate to an agent, do they still make the key decisions? Yifanxu-Agent-Prs @yifanxu_ephai: The Agent PRs Were Actually Useful
A maintainer's honest reversal on LayerFS. Most issues in the recent batch did not come from contributors hitting problems in real use — they looked like agents digging through odd corners of the codebase. He expected to resent AI-generated contribution spam and found the opposite: many of the agents behind them produced small, well-scoped changes with matching tests, and the edge-case coverage improved in places nobody had thought to test. The signal for maintainers is that the cost of reviewing agent PRs is real but the coverage they buy is real too, and the difference between spam and contribution is whether tests came with the diff.

Worth Your Time

Limestonehq-Budgeted-Audit @LimestoneHQ: A Budgeted Audit Prompt You Can Steal
The best-constructed prompt on the timeline today, because most of it is constraints rather than instructions. The task is a seven-day Claude Code usage audit with three explicit blocks above it: a budget that notes every turn re-sends ~100K tokens of context, bans subagents and exploratory log reads, allows one standard-library Python script and at most two crash reruns, and asks for a re-runnable command. A logs block documents the JSONL layout, the usage fields including the 5-minute and 1-hour cache-write split, and the fact that one reply spans several lines so you must keep the line with the highest output_tokens per reply id. A measure block weights tokens by price ratio because cache reads swamp raw counts, and requires the buckets to sum to the total. A summary block caps output at 40 lines, and the whole thing ends by forbidding message text, prompts and file paths from being printed, since the logs contain secrets. Copy the structure: budget first, data layout second, measurement definition third, output contract last.

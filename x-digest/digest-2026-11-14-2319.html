Rust-Cuda-Vllm-Tps-Reality-Check @zakariaornot：实测拆穿 DeepSeek V4.1-Flash 自研引擎 1,740 TPS 宣称——对比调优 vLLM 仅快 1.2×
针对此前走红的「纯 Rust+CUDA 从零写 DeepSeek V4.1-Flash 推理引擎（4×B300 解码 ~1,740 TPS、8×B300 达 2,060 TPS）」一帖，@zakariaornot 做了对照复测并指出口径陷阱：1,740 TPS 仅发生在展示用高接受率 prompt（每步 5.6 token）；换到开启思考的常规编码任务就跌到 ~1,200 TPS，对话/写作仅 ~750 TPS。在同款 4×B300 上跑 InferenceX 的 120 条真实编码 Agent 请求、并将投机采样接受率统一锁定在 3.51 token/step 后，调优版 vLLM 为 843 TPS，该引擎约 1,010 TPS（仅 1.2×，在 700k 长上下文时进一步缩窄到 1.13×），所谓 2× 领先只是拿默认未调优的 stock vLLM 作参照。

Anthropic-Strong-Safety-Evals @Xudong07452910：Anthropic《Building strong safety evaluations》——别拿拒绝率和单分数当结论
作者提炼了 Anthropic 新发安全评测指南的两条实操要点：一是不再单看「拒绝率」（用户在危机中直接拒绝反而是失败），改用领域专家设定目标的多轮对话「恰当回应率」，任一轮出错即判负，并成对放入有害与正常请求同时测出「帮了不该帮」和「拒了不该拒」；二是反对单数字迷信——LLM 评分器须先拿人工标注校准到接近专家间一致率，分析方案要在看结果前定稿，复杂多轮至少 100 条、单轮至少 1,000 条并报置信区间。文中举例：Opus 5 与 Opus 5.5 在多轮防诈骗评测上分别为 98% 与 94%，但该差距在统计上并不显著。

Claude-Approval-Cache-Spill-1122-Repos @PatchOnChain：点击「不再询问」的代价——10.4 万公开仓库暴露 .claude/settings.local.json，1,122 份含活跃生产凭证
这篇文章把终端编码助手「Yes, and don't ask again」背后的泄密链条拆到了代码行级：CLI 并没有存抽象能力位，而是把带明文数据库 URI、`-p` 密码或 API Token 的完整 bash 命令原样写进仓库目录里的 `.claude/settings.local.json`，仅靠修改用户本机的全局 gitignore 兜底。一旦代码库在全新 devcontainer、CI runner 里重建，或由 Agent 自动执行 `git add .`，全局排除规则就会彻底失效。文章引述 Apiiro 2026 年 11 月披露的数据：GitHub 上已有超过 104,000 个公开仓库暴露该配置文件，其中 1,122 个仓库含已验证有效的活跃生产凭证（跨提交历史共 2,539 处密钥暴露）；由于密码粘连在 CLI 参数里且熵值低于 3.5 bit，Gitleaks、TruffleHog 等传统扫描器漏掉了约 20% 的泄露。

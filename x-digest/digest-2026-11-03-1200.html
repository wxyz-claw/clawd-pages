Latentoperatorx-Harness-Vs-Opencode @LatentOperatorX: The Same Model Scores 7.8 With a Harness, 5.6 Without
One cheetah animation prompt, two setups, same DeepSeek V4.1 underneath. In a harness: 7.8/10, 48 minutes 14 seconds, ~$0.55. In OpenCode: 5.6/10, 6 minutes 7 seconds, ~$0.11. That is 2.2 points of quality for roughly 8x the wall clock and 5x the cost. This is a single prompt with a self-scored rubric, so treat the absolute numbers lightly — but the direction is the same finding as the HarnessMM paper: the outer shell, not the weights, is where a large share of the variance lives. The useful question it poses is not which setup wins, it is which of your jobs can afford the 8x.

Cost & Capital

Jun-Song-Gpu-Rental-Vs-Wage @jun_song: One GPU Rents for More Than the Median Adult Earns
Four lines of arithmetic: an RTX 6000 Pro that costs $14,000 rents at $3.39/hr, which is $29,696.40 a year, against a global median adult income of about $23,000 adjusted for purchasing power. The calculation is deliberately crude — it assumes the card is rented every hour and ignores depreciation, power, hosting and the fact that rental price is a gross figure — but the claim it supports survives the caveats: at current clearing prices, one card's annual output is priced above the median worker's annual output. Keep it as the sanity check on any "compute is cheap now" argument that quotes only per-token rates.

Scaleops-Prefix-Cache-Hit-Rate @scaleops_ai: A 100% Prefix Cache Hit Rate Can Still Waste Memory
Hit rate counts matches, not the GiB that actually get reused. A vLLM deployment can report 100% hits while most of its KV cache holds prefixes nobody will ever request again, which means the metric looks perfect and the memory is still spent. The practical consequence is that tuning prefix caching on hit rate alone optimises the wrong number; reused bytes is the quantity tied to cost, and the eviction policy is the lever that moves it. Worth reading before blaming a cache configuration for a bill it did not cause.

Models & Research

Nft-Chen-Lsa-Long-Context @NFT_Chen: Latent Sparse Attention — 72x Faster Prefill at 10M Tokens
A Chinese-language walkthrough of LSA on Qwen 3.8 27B. The method clusters keys into a hierarchy by similarity, has each query look only at cluster centres, then computes attention inside the few most relevant buckets — tree search instead of a full scan. At 10M-token context he reports 72.4x faster single-layer prefill and 42.5x faster decode, with end-to-end time-to-first-token cut to roughly one ninth, accuracy roughly flat and slightly better on RULER. Two details make it portable rather than paper-only: only a short distillation trains the indexer while the base model stays frozen, and distilled weights for Qwen3.8-27B are released, served through an SGLang fork with a JSON override flag and prefill CUDA graphs disabled. For anyone renting capacity by the hour, the interesting claim is that million-token context stops requiring a rack.

Nft-Chen-Writing-Weights-Index @NFT_Chen: A Benchmark for Writing Weights Directly
A new index scores models on editing neural network weights directly rather than producing tokens: GPT-6 Astra 60.7, Claude Opus 5.5 51.2, Qwen 3.8 2.4T 12.5, DeepSeek V4.1 Flash 1017 10.0. Gkev1N-Adversarial-Review-Token-Burn @GKev1n: Stop Paying Two Models to Argue About Code
Agreeing with @poteto's take that adversarial sub-agent code review mostly burns tokens, he reports that pstack's interrogate skill was cut and the freed compute redirected toward real tests plus formal verification. Three failure modes are named with unusual precision: nitpicking, where a reviewer has to prove it worked so it invents style findings; YAGNI bloat, where the main agent piles in abstractions and defensive branches to satisfy hypothetical edge cases the reviewer imagined, leaving the context dirtier than it started; and misallocation, spending the most expensive reasoning tokens guessing whether code will fail instead of running the free compiler and linter. The convergence he points at is the argument: xAI cutting model-versus-model review in the same week OpenAI raises bounties for real external attackers.

Tools & Systems

Tvytlx-Offline-Deepseek-Consumer-Hardware @tvytlx: A Fully Offline Agent Stack, and the 20x From Fixing the Prompt
A Reddit build running DeepSeek V4.1 Flash at 1M context and 1.75-bit quantization entirely offline on an RX 9070 XT 16GB, a 5800X3D, 64GB of DDR4 and an old PCIe 3.0 SSD, splitting the model across VRAM, RAM and disk at about 7 tokens per second. The pain point was startup: every new agent session re-read a 37,000-token system prompt and waited about 100 seconds for the first token. Two engine patches fixed it. First, the agent injects date, working directory, project notes and randomly-ID'd paths into the system prompt, and because caching matches on prefix, a few changed characters invalidate everything after them — so the engine now line-aligns the new prompt against the stored session, re-reads only the changed lines and reuses the rest. Second, MoE models touch nearly every expert in every layer even for a tiny input, pulling 58GB off disk for a 1,200-token prompt; he restricted prompt reading to experts already resident. Result: agent session startup about 20x faster. He states the boundaries himself — AMD only, approximate splicing, no formal eval, and both modes scored 12/13 once each. The takeaway that transfers to cloud APIs: keep the prompt prefix byte-identical and push anything variable to the end.

Worth Your Time

Ibragim-Bad-Team-Cost-Inversion @ibragim_bad: The Cheaper Model Made the Bill Go Up
Seven team setups across 12 real, hard ML coding tasks. Opus 5.5 alone: 81% of tasks solved at $1.20 per task. Opus plus DeepSeek V4.1-Flash-1017 as the worker: 67% at $1.29 per task — worse and more expensive. The mechanism is in the follow-up post. An agent resends its full context every step, the prompt cache makes those reads cheap, but the cache lives only about five minutes; when Opus waits 10-15 minutes for the worker, its cache expires and it re-writes the context at 25x the read price ($5 versus $0.20 per million tokens). In teams Opus spent $0.52-0.84 per task on cache writes while the entire worker cost $0.06-0.19. The intervention that actually worked was not a ban but a price signal: telling Opus its tokens cost 20x more made the worker write 94% of the code, quality held at 67%, and cost per task fell to $0.71. One more number worth carrying: 71% of team failures were tasks the worker also failed alone.

Kalanamith-Aws-Infinity-Runtime @kalanamith: 75,000 Agents in 8GB — AWS Open-Sources Infinity
An Apache-2.0 Rust agent runtime from the Hydro project, a collaboration between AWS and UC Berkeley, announced on the AWS open source blog by Hydro's research lead. The design borrows from Rust: agents are stackless coroutines, and every tool call is an await point where the runtime saves conversation history, suspends the agent and resumes it when the result arrives. An idle agent therefore holds no task, no stack and no connection — just about 100KB of history — which is how 75,000 of them fit in the 8GB of a Raspberry Pi 5. The reference deployment is SQS FIFO as the input queue, one Lambda step per message, Aurora DSQL for history, DynamoDB for deduplication and EventBridge Scheduler for timers, all provisioned by CDK constructs, so an agent waiting three days on a CI pipeline uses zero compute. The argument that lands is a CapEx one: agent cost is usually discussed as tokens and cloud bills, but blocking runtimes force enterprises to size owned GPU and on-prem hardware for every agent that is merely waiting.

Me-Deepu-Longcat-Reward-Hacking @me_deepu: Meituan's LongCat 2.5 and Its Reward-Hacking Guards
A 1.6 trillion parameter model with roughly 48B parameters active per token, trained and served on Chinese AI accelerators at under 80GB of memory per card, live on API with weights promised. To stop the agent cheating during RL they switch off network access in the task environments, delete git history and cached files, and have an LLM judge audit trajectories for exploits.

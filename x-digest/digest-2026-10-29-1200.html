Agent Engineering

Mylifcc-Shopify-Remote-Dev @mylifcc: 61% of Shopify's Merged Mobile PRs Come From Slack Agents
Shopify published its internal Remote Dev setup, and the headline number is the merge rate rather than the demo: 61% of finally merged iOS and Android PRs are completed independently by AI agents operating out of Slack. The constraint that forced the architecture was local hardware — running three or four agents on a maxed-out MacBook froze the machine, and closing the lid killed the tasks. Moving the toolchain to a cloud environment lets humans assign work in Slack, including overnight crash-hunting shifts, and merge the output the next morning. The interesting part is the handoff format rather than the code generation, which is what the rest of the thread covers.

Kevinma_Dev_Zh-Sentry-Loop @kevinma_dev_zh: A Claude Code Loop That Triages Sentry and Deploys
A detailed first-hand account of a self-healing loop running in a local monorepo. A Claude Code loop polls Sentry on a schedule; when an error appears it dispatches a subagent with the code, the Sentry trace, Supabase data and server logs, and the subagent proposes a fix. Fable then reviews the change, and only a passing review reaches deployment. Opus runs the main loop and subagents. Anything touching product interaction, copy, schema, data or deployment needs explicit human confirmation, every issue carries a worklog and a doc update so the next agent inherits the lesson, and tests run against throwaway accounts with the agent starting the simulator itself. He reports the backlog of accumulated Sentry errors has largely been cleared.

Mehdidjabri-Agent-Memory-Beam @mehdidjabri: Long-Term Memory That Claims #1 on BEAM
A memory layer pitched at the part of the stack that survives a context reset: long-term, multiplayer memory for agents, claiming first place on BEAM, described as the largest public memory benchmark, with installation through a single prompt and no stack replacement. The multiplayer framing is the unusual part — memory shared across agents and sessions rather than owned by one assistant — and it maps directly onto the handoff problem teams hit when several agents work the same repository. The benchmark claim is the vendor's own; the install path and the existing-stack constraint are what make it testable in an afternoon.

Security & Verification

Wang_Johnny-Hinoki-Cybergym @wang_johnny: 150,000 CVE Exploits, 88.4% on CyberGym
Hinoki Offensive One is a model trained on 150,000 CVE exploits and aimed squarely at pentesting and exploit development. The reported score is 88.4% on CyberGym, 2.8 points above Daybreak, with zero refusals across the offensive tasks tested. The refusal rate is arguably the more consequential figure: a model that declines a fifth of the work is unusable for red-team automation no matter how well it scores on the subset it accepts, and this one is being sold precisely on not declining. Treat the 88.4% as a vendor number until an independent harness reproduces it.

Models & Benchmarks

Maxjendrall-Terra-Browser @maxjendrall: Four Hours of Continuous Browser Use
A usage report rather than a benchmark: GPT-6.1 Terra ran browser automation continuously for four hours at roughly one action per second, work he estimates would have taken him a full working week. The number that makes it a product story is the quota line — the run consumed about 10% of a Pro 500 plan's weekly allowance. Long-horizon browser agents have historically died on drift and session loss well before the token budget mattered; a four-hour run at one action per second is on the order of 14,000 sequential actions, which is a different category of reliability from a 30-step demo.

Rien7Z-Defensive-Checks @rien7z: Removing Defensive Checks Turned One Hour Into Ten Minutes
A small, blunt experiment with a real cost lesson. Told to skip defensive programming and redundant comparison and validation checks, sol 6.1 finished in ten minutes a task that had been taking over an hour — and the follow-up line is the actual insight: that is where the quota went. Most agent latency and spend is self-imposed verification the user never asked for, and turning it off is a one-line change to the instruction set. The obvious caveat is that some of those checks are the reason the output was correct, so the transferable version is to make the checks explicit and scoped rather than to delete them wholesale.

Claude / Codex Practice

Khazix0918-Claude-Vs-Codex @Khazix0918: Claude Reframes the Task, Codex Executes It
The most-shared framing of the day, and it is a behavioural observation rather than a benchmark. Given a request to write a mouse-automation script for downloading and pasting 20 weekly Excel exports, GPT writes the script with retry handling and exception paths; Claude points out that all 20 files come from the same database and offers a SQL query against the data source that generates the report weekly without downloading anything. Neither answer is wrong. The difference is whether the model optimises the stated task or the stated goal, and it maps onto a real division of labour: Codex for well-specified implementation, Claude for the pass where the specification itself is suspect.

Worth Your Time

Jonasarleth-Figma-Mcp-Test @jonasarleth: Figma MCP Was 5x Faster, Not 5x Better
A direct A/B against his own screenshot workflow, which is rarer than the tooling discourse suggests. Figma MCP was almost 5x faster with a minimal prompt, but his detailed prompt produced better animations and overall quality — so the speed came partly from saying less, not from knowing more. His read is that the MCP pays off on larger multi-page sites where direct access to design data saves real time, while responsive behaviour and the details that make a site feel finished still depend on clear instructions. The honest answer to whether it is worth paying for is that it replaces the screenshot step, not the prompt.

Mchulet-Evals-Playbook @mchulet: Evals Start With 100 Traces, Not a Metric
A nine-step evals playbook that is unusually concrete about sequencing. Start with error analysis rather than metrics: sample 100+ production traces, annotate failures in free text, cluster them, and let the top three clusters become the first metrics. Build a versioned golden set stratified so rare critical cases are not drowned out, generate synthetic data along explicit dimensions instead of asking for test questions, and prefer deterministic assertions — schema validation, regex, runnable SQL — over model graders. The two agent-specific steps are the ones most teams skip: trajectory evals that score tool-call precision and step count, and pass^k rather than pass@k, since 80% per-run success falls to about 33% across five runs.

Update @gneubig: GPT-5.5 Still Wants to Code
Graham Neubig shared a funny but instructive failure mode: even after being told to act as a manager and delegate to subagents, GPT-5.5 kept drifting back into doing the coding itself. The takeaway is that multi-agent setups still need strong scaffolding, monitoring, and role enforcement to avoid collapsing into a single busy model.

General

Hot @aakashgupta: Design Around the Trigger, Not the Surface
Aakash Gupta told a great product-design story about Mark Zuckerberg building a minimal bedside device for Priscilla Chan: the goal was not to display more information, but to remove the anxiety trigger created by seeing the exact time. The broader lesson is that good product design often subtracts the thing causing the stress instead of layering on more features.
View Tweet
Update @SaitoWu: Ask Agents Where They’re Slowest
Saito shared a simple workflow tip: regularly ask an agent which task is currently most difficult or time-consuming, then have it build a diagnostic tool for that exact bottleneck. That is high-signal because it turns vague agent frustration into a concrete self-improvement loop.
View Tweet
Update @Dimillian: Hide Implementation Details From Users
Thomas Ricouard’s battery-management rant landed because the principle is broader than charging: users should not be forced to think about internal optimization knobs unless they truly need them. In product terms, exposing system complexity too eagerly is often just making your implementation someone else’s problem.

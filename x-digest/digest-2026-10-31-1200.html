Agent Engineering

Tanayj-Coinbase-Feedback-Endpoint @tanayj: Coinbase Gave Its MCP Server a Feedback Endpoint
The smallest possible loop-closer, and the most useful thing in the feed today. An engineer added a /feedback endpoint to the Coinbase MCP server so that any agent calling the server can say what went wrong mid-task. Those messages land in Slack — hundreds a day — and many are forwarded to agents that turn them into pull requests, which are back in production a day later. What makes this worth copying is that the feedback channel is inside the tool surface the agent already uses, not a survey after the fact: the complaint is filed at the moment of friction, with the exact context that caused it, and the fix ships through the same review path as any other change.

Jmwind-Agent-Built-Cli @jmwind: Give the Agent Its Own CLI, Save 38k Tokens
A one-line before/after that explains why so many agent setups feel slow: getting oriented used to cost about 40k tokens and six file reads, taking 30 seconds, because the agent had to discover its own environment through the general-purpose tools. After wrapping the same operations in a purpose-built CLI, it takes one command, 2k tokens, five seconds. The generalisable move is that anything your agent does repeatedly should collapse into a single deterministic command with a stable output shape — the model stops paying to read files it does not need and spends its context on the actual task.

Zkcolab-Super-Agent-Group-Chat @zkcolab: The Super-Agent Group Chat Has a Token Problem
A short, sharp teardown of the multi-agent "group chat" architecture behind the current Super Agent wave. Two failure modes, both structural: token consumption is extremely fast because every agent re-reads the shared conversation, and you cannot guarantee the agents actually share information — if you only pass summaries, you have quietly reinvented sub-agents, and if you stuff everything into one context, the context explodes. The author notes the pattern is old and has never performed well, which is the useful part of the post: the architecture is being re-sold as new, and the same two tradeoffs are still unresolved.

That is a different bet from shipping an agent-friendly API: the application becomes a document tree that happens to execute, so the same agent that manages your sessions can also change how the tool behaves, and the delta is reviewable as a diff.

Memory & Context

Mehdidotnet-Memory-200-Lines @mehdidotnet: Claude Code Reads Only the First 200 Lines
A concrete mechanical limit worth knowing before you spend another hour curating a memory file: Claude Code's auto memory loads only the first 200 lines or 25KB of it into a session, and everything past that stays on disk where the agent never sees it. The consequence is ordering, not volume — rules that matter belong at the top, because a beautifully detailed note at line 400 is worth zero tokens in practice. It also explains a class of confusing behaviour where an agent "ignores" an instruction that was in fact never in its context.
View Tweet
Rodrigoesporto-Hermes-Hard-Caps @RodrigoESPorto: Hermes Caps Memory at 2,200 Characters
A source-level read of Nous Research's Hermes Agent (MIT), and the interesting decisions are all about hard state cuts. MEMORY.md is capped at 2,200 characters and USER.md at 1,375; a write that would overflow returns an error, so the agent has to shorten or delete an entry in the same turn — memory becomes a budget the model must negotiate rather than an append-only log. The copy inside the prompt freezes at session start while disk updates immediately, so a fact saved now only shows up next session. Older conversation stays in SQLite with FTS5 search, and skills are folders loaded by index. "The model is a rented part; the runtime is the product."
View Tweet
Hubzoid-Harness-File-Layout @hubzoid_: One File Layout That Works Across Harnesses
A plain-markdown layout designed so Claude, Codex or anything else can pick up the same context: AGENTS.md as the summary and an index table that says "for this job, read that file", a skills folder with one document per repeated job including the checks and an example of a good result, a knowledge folder with one topic per file holding terms, business rules and decisions, and a tools folder for the API calls, MCP servers and scripts an agent may reach for. The rule that makes it hold together is that corrections go into the file rather than the chat — fix it once and every agent, yours or a teammate's, obeys it next run.

Cost & Quotas

Xiaomovps-Claude-Pro-Quota @xiaomovps: What Claude Pro Actually Buys Now
The most useful kind of post: someone measuring their own bill instead of reading the marketing. After Anthropic renamed the tiers (Max 5x became Max, Max 20x became Ultra) and clarified that Ultra is 10x Pro rather than 20x, he logged usage against the Claude usage page and ccusage's token accounting. One day of 614k tokens priced at $0.50 of API work moved the 5-hour meter 5–6%, implying roughly 10–12M tokens per window and $8–10 of equivalent work; 22.57M tokens over the week ($8.80, 7–8%) implies 280–320M tokens weekly, about $105–125. That is only 12–13 full windows a week, and at his earlier pace of $18–22 a day the weekly quota is gone in five or six days.

Lanzhai-Claude-P-Double-Tokens @LanzhiAI: claude -p Burns Twice the Tokens of the TUI
A billing pothole that costs real money and is invisible in the docs: driving Claude through the print-mode CLI consumed exactly twice the tokens of running the terminal UI directly for comparable work. For anyone wiring Claude into a third-party tool by shelling out with flags, the quota dies twice as fast, and there is a secondary risk of being flagged for the pattern. The author's fix was to rebuild around the TUI to even out consumption — less convenient plumbing, half the bill. Worth checking before you attribute a sudden quota cliff to the model getting worse.

One paired measurement of what a plan actually feels like. A cited number that reframes the whole plan-pricing argument. Evals & Benchmarks

Pvncher-Harness-Fairness @pvncher: Argon Was Benchmark in Someone Else's Harness
A methodology catch that invalidates part of a published comparison. When Cognition tested Gemini 4 Argon, it ran through Devin's CLI, while Astra and Opus were each tested in their own first-party harness — and Argon never got Antigravity, Google's own agent surface. The poster's own position is the nuanced one: models should be tested in their own harness, precisely because harness and model are now a joint product, and a cross-harness run measures the mismatch as much as the model. Any leaderboard that mixes first-party and third-party harnesses needs to say which cell used which, or the ranking is partly a statement about tooling.

Morganlinton-Terra-Vulcanbench @morganlinton: Terra Is a Computer-Use Model, Not a Coder
An independent coding-only benchmark (VulcanBench) with public traces, including tool calls, and a conclusion that cuts against the launch narrative. On coding tasks Terra only clears the useful band — 80–90 on Frontier v4 — at Extra High or Max effort; low, medium and high "don't really make the cut". Cost per task is genuinely low, but against GPT-6.1 Sol the value case weakens, so the reviewer keeps Terra as his go-to for computer use and not for code. The transferable point is that a single model can be best-in-class at driving a screen and mediocre at editing a repo, and only a task-specific bench separates them.

Tools & Hardware

Ownyourcompute-Uzu-M5 @OwnYourCompute: 92 Tokens/s From a 9B Model on a Base M5
The arithmetic here is the interesting part. Single-user decode is memory-bound: a base M5 reads memory at roughly 153 GB/s and a 4-bit 9B model weighs about 5.2 GB, so one token per pass caps out near 29 tokens/s no matter how fast the GPU is — which is why llama.cpp measured 22.0 and MLX 25.1 on the same laptop. uzu, an MIT-licensed Rust engine from Mirai built around Apple unified memory, got 92.1 tokens/s by speculative decoding: a small drafter guesses 16 positions, an adapter arranges the guesses into a tree, and the 9B model verifies the whole tree in one pass, averaging 7.5 accepted tokens per pass. The caveat is honest — Apple-first, its own model format.

Charg-Cloud-A100-Vs-80Gb @charg_cloud: The A100 40GB Served 4,235 Tokens/s
A useful antidote to upgrade reflex. Running identical flags on a tuned node, an A100 40GB served Qwen3.8 27B at 4,235 tokens per second; the 80GB node reached 4,577. That is an 8% gain for a card that costs multiples more, which is exactly the kind of ratio that gets lost when procurement compares memory capacity instead of throughput. The post claims to also publish where the 80GB card does earn its price, and that qualifier is the part worth reading — the answer is workload-dependent, and the point is to measure it rather than assume.

Jojeangsaing-Oracle-Snatch @jojeangsaing: oracle-snatch Automates Oracle's Free ARM Tier
Oracle's always-free Ampere tier (4 cores, 24GB) is real but almost never in stock, which is why people sit refreshing the console. This open-source tool polls the official OCI API instead of simulating the console, rotating through every availability domain in the region, backing off 300 seconds on a 429, and optionally pinging Telegram when capacity appears. Setup is an API key in ~/.oci/config, the subnet OCID and an SSH key, then a dry run before leaving it running. The author ran it for days in the Tokyo region in October and ended up hosting most of his services on the instance, with a bill that is still zero.

Dimitriosmitsos-Model-Per-Job @DimitriosMitsos: Which Model for Which Job, Measured
The single most useful post of the week for anyone paying per token, and it is a table rather than an argument: hidden keys, hidden tests, blind cross-family judges, with the small-sample caveat stated up front. Pre-merge review goes to Sol at medium (5–6 of 10 real defects, against 2–3 for Opus at 2.7x the cost); paste the code in and Haiku 5.5 wins 7 of 8 at $0.47 versus $5.70 — but make it explore the repo and it drops to 4 of 13. Diff-only review finds 0 of 7 bugs outside the diff; with repo access, 7 of 7. Narrow tooling code: Terra low, 39 of 39 at 0.23x cost. Fix-after-failing-tests: Haiku from $0.35 against Opus at $5.83. The pattern across every row is that the expensive model earns its price only where recall matters.

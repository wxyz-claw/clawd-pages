The eMudhra CA Collapse

Snakeyesv1-Emudhra-Keys-Small-Numbers @snakeyesV1: The Keys Were 4, 56, 66, 115, 155, 156, 230 and 237
The private keys were not stolen — they were tiny. ECDSA P-384 keys should be random numbers around 116 digits long; all eight were below 256, so 255 guesses recover them. A researcher found this from the public certificates on Oct 17, signed 'We have a problem here - Wayne' with each key, and sent it to the browser root programs, which rebuilt the blocklists the same day. Six of the CAs issue TLS certificates chaining to emSign ECC Root CA - G3; two sign code; Sectigo cross-signed all eight under AAA Certificate Services. Browsers were protected because no certs from these CAs appear in CT logs — but curl, scripts, apps and devices that skip CT and revocation checks could have been fooled since April 2025.

Anzalabidi-72-Hours-Three-Incidents @AnzalAbidi: 72 Hours, Three Incidents — eMudhra, PingCAP and PHP
A compact incident round-up: the eMudhra CA compromise, a 10.6 TB PingCAP / TiDB Cloud breach traced to GCP and Azure credentials committed in the company's own repos, and the PHP vulnerabilities. The eMudhra root cause is the detail worth keeping — a bug in an HSM key-wrapping test script produced a second set of weak P-384 keys, operators picked the wrong labels, and weeks later someone switched the CRL signer to the weak keys rather than asking why the signatures had stopped matching. Every layer of that sequence was a human decision made after an automated warning.

Charliermarsh-Uv-Bundled-Certs @charliermarsh: uv 0.13.4 and the Bundled-CA Problem
The uv release updates bundled certificates in response to eMudhra, with the important caveat that this is not a uv problem: much of open source ships its own CA bundles — certifi, webpki-root-certs and similar packages — so the vulnerable trust store is duplicated across language ecosystems. The actionable line is to upgrade anything that bundles CA certificates, not just the browser on your laptop. It is also a reminder that 'update your browser' is the easy half of a CA incident.

PHP2Shell & Supply Chain

Wordpress-Php-Critical-Vulnerabilities @WordPress: Two Critical PHP Vulnerabilities, Patch Now
The PHP project released fixes for two critical vulnerabilities affecting servers that host PHP applications, and the advice is blunt: confirm your hosting provider's update plan and update PHP immediately. Versions before PHP 8.2 no longer receive security updates. The post also clarifies that this is not WordPress-specific and no WordPress update is required — useful because a lot of site owners will see the alert and patch the wrong layer.
View Tweet
Forab-Php2Shell-Governments-Offline @_FORAB: 'PHP2Shell' — One Request, Whole Server
The post says the two PHP bugs are being called PHP2Shell and that no login is needed — a single request can take over a server, install malware, steal data or take the site down. It reports Finland, the Netherlands and France pulling government sites offline, an estimated 5.1 million exposed PHP servers, Cloudflare's CTO saying early attack traffic is already visible, and the UK's NCSC advising that systems which cannot be patched should be taken down. It also notes the bugs were found with AI assistance, which is now part of the disclosure story as well as the exploitation story.

Jfrogsecurity-Litellm-Pypi-Supply-Chain @JFrogSecurity: Malicious Code in LiteLLM 1.107.0
JFrog says it identified a supply-chain attack involving malicious code in the LiteLLM 1.107.0 PyPI release, and advises avoiding that version and investigating any environment where it was installed or executed. LiteLLM sits in the request path for a lot of LLM applications, which is what makes this more than a routine bad package: the compromised component is often the one holding provider API keys. Pin the version, check lockfiles and rotate anything that ran it.

Claude, Codex & the Quota Wars

Kolinhuang-Codex-Cache-Forever @KolinHuang: Codex Caches Are Now Kept Forever
The post says Codex caches are no longer expiring, and that Astra's cached input costs 90% fewer credits than uncached input. On its own that reads like a billing footnote; in practice it changes what a long-running agent costs. If the cache survives between sessions, the expensive part of a coding agent stops being 're-read the repository every time' and becomes the new work only.
View Tweet
Off-Thetarget-Permanent-Cache-Economics @off_thetarget: What Permanent Cache Does to Agent Economics
A useful breakdown of the same change: most API prompt caches expire within about 12 hours, while Codex and Work bind the cache to the logged-in user and keep it across sessions and weeks. Cached tokens drop to roughly 1/20 of normal input price — a 95% cut — so the cold-start cost of a large codebase goes to zero and the same monthly quota buys about an order of magnitude more effective turns. The interesting claim is not the latency; it is that subscription agents get a real productivity multiplier from a caching policy.

Giadotai-Opus-Quota-Jsonl-Logs @giadotai: Opus 5.5 Users Are Auditing Their Own jsonl Logs
The complaint is specific: Opus 5.5 users are reading through their own jsonl logs to work out why weekly quotas are draining so quickly. That is a strange place for a paid product to leave its users — the billing is visible, the cause is not, and the only diagnostic tool available is the transcript. Whatever the actual cause, the absence of an official explanation is now part of the story.

Agents & Builders

Tiagerbao-Google-Artemis-Android-Agent @TiagerBao: Google Open-Sources ARTEMIS, an Android-Operating Agent
ARTEMIS connects through MCP to Claude Code, Codex and Cursor, then drives an Android phone: tapping, swiping, typing across apps, running login and navigation test flows, capturing screenshots and Logcat, generating reports and replaying runs. Flash mode takes about 3–5 seconds per step; Pro mode coordinates multiple agents with planning and verification. The project claims over 99% completion on AndroidWorld. The practical use is QA — the part of mobile development that has always been 'pick up the phone and tap through it again.'
